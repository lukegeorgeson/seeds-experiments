# Product Principles

These principles define how Seeds should behave as a product. They are intended to keep the tool focused, differentiated, and useful as the product grows.

## 1. Human-led, AI-accelerated

Seeds exists to support human taste and judgement, not replace it.

The system should propose, provoke, and expand. The user should decide, shape, and refine. Every major workflow should reinforce the idea that authorship remains with the human operator.

Implication:
- AI should generate options, not final authority.
- User actions should materially influence future rounds.
- The system should never behave as though its first answer is the correct answer.

## 2. Start with ingredients, not conclusions

Seeds should operate at the level of creative ingredients rather than polished outputs.

The product should help the user discover and combine seeds of direction before trying to formalize them into a final narrative.

Implication:
- Cards should stay short and atomic.
- Early rounds should privilege possibility over polish.
- The system should avoid over-writing or over-explaining.

## 3. Breadth first, coherence later

Strong strategic and creative work often begins with multiple possible paths before converging into a tighter direction.

Seeds should respect that natural movement rather than collapsing too early into one answer.

Implication:
- Round 1 should generate real variety.
- Later rounds should gradually synthesize and sharpen.
- The system should avoid false certainty in early stages.

## 4. Selection is signal

Every meaningful user interaction should be treated as input to the next synthesis.

The product should treat selection, editing, note-taking, user-authored cards, dragging, locking, and riffing as signals of intent rather than superficial interface actions.

Implication:
- The next round should reflect what the user actually did.
- Edited and user-created cards should carry more weight than untouched AI cards.
- Locks should preserve important ideas across future rounds.

## 5. Visual canvas over chat log

Seeds should prioritize a visual, spatial, canvas-based workflow over a chat-based experience.

The primary interaction should be through cards on a structured canvas, not through long conversational exchange.

Implication:
- The main workspace should feel like a blank but active creative surface.
- Cards and columns should be the main interaction surface.
- Any AI thinking or status messaging should remain secondary and lightweight.

## 6. Loose structure beats rigid templates

Seeds should provide enough structure to help the user think, but not so much that it becomes formulaic.

The system should begin with a useful creative flow and allow that structure to evolve as direction becomes clearer.

Implication:
- Initial columns should be guided, not overly fixed.
- Later rounds can rename or reshape columns based on the signal.
- The system should avoid locking the user into a single strategic framework.

## 7. Atomic cards, high legibility

The card should remain small, scannable, and combinable.

If cards become too dense, the product loses speed, composability, and clarity.

Implication:
- Cards should generally be one idea each.
- Card copy should be short, directional, and suggestive.
- The UI should be optimized for scanning and comparison.

## 8. Local exploration and global evolution are different actions

Not every creative move should require a full new board.

The product should support both local riffing on one promising seed and global round-based evolution across the whole canvas.

Implication:
- There should be a lightweight way to explore variants of one card in place.
- There should also be a separate action to generate the next full round.
- The system should make these two actions easy to distinguish.

## 9. Preserve history, support branching

Creative development is rarely linear. Users should be able to revisit and branch earlier thinking.

The product should treat rounds as navigable creative states rather than disposable rerolls.

Implication:
- Every round should be preserved as a canvas state.
- Users should be able to return to previous rounds.
- The underlying system should support branching even if the first UI keeps it simple.

## 10. Do not overbuild v1

Seeds should begin by solving one focused problem extremely well: helping a single creative user go from brief to sharpened strategic direction.

The product should not dilute itself by trying to solve collaboration, presentation export, retrieval, and workflow management all at once.

Implication:
- Collaboration is roadmap, not core v1.
- Corpus/RAG is roadmap, not core v1.
- Markdown export is enough for v1.
- The early product should optimize for quality of ideation and refinement, not platform breadth.

## 11. The system should feel calm, crisp, and premium

Seeds should feel like a thoughtful creative tool, not a noisy AI utility.

The environment should support focus and confidence, even when the work itself is exploratory.

Implication:
- The interface should open as a clean canvas.
- Controls should remain secondary to content.
- Motion, layout, and component design should feel light and intentional.

## 12. Help the user make better work, not just more work

The goal of Seeds is not simply more ideas. The goal is better direction.

The system should generate enough variety to be useful, but it should ultimately help the user move toward sharper judgement, stronger combinations, and more usable strategic shapes.

Implication:
- The system should favor meaningful variation over superficial quantity.
- Rounds should progressively improve the signal-to-noise ratio.
- Output should feel more coherent and more usable than the input state.
